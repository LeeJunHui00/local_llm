# 프로젝트 규칙 파일 템플릿

사내 저장소 루트에 복사해서 쓰는 파일임. CLI 에이전트가 세션마다 자동으로 읽음
(Claude Code 계열이면 파일명 `CLAUDE.md`, 다른 에이전트면 해당 규격의 규칙 파일명으로).

**에이전트 출력 품질의 대부분이 이 파일에서 결정됨.** 모델이 약할수록 효과가 커짐 —
좋은 모델은 스스로 추론해 메우지만, 사내 모델은 안 알려주면 그냥 틀림.

작성 원칙: 추측하면 틀리는 것만 적을 것. 코드를 읽으면 아는 내용은 넣지 말 것
(토큰만 소모하고 정확도는 안 오름).

아래 `<>` 부분을 실제 값으로 채워 사용.

---

```markdown
# <프로젝트명>

## 빌드 / 테스트

- 설정: `cmake -B build -DCMAKE_BUILD_TYPE=Debug -DCMAKE_EXPORT_COMPILE_COMMANDS=ON`
- 빌드: `cmake --build build -j`
- 단위 테스트: `ctest --test-dir build --output-on-failure`
- 단일 테스트: `./build/tests/<test_bin> --gtest_filter=<Suite>.<Case>`
- 크로스 컴파일: `<툴체인 파일 경로 / 환경 설정 스크립트>`
- 빌드 산출물: `build/bin/`, 심볼 포함본은 `<경로>`

주의: <예 - 최초 빌드는 30분 소요됨. 전체 재빌드 금지, 변경 타깃만 빌드할 것>

## 소스 트리

| 경로 | 설명 |
|---|---|
| `src/core/` | <핵심 로직. 여기 수정은 영향 범위가 넓음> |
| `src/hal/` | <하드웨어 추상화. 타깃별 구현 분기> |
| `src/net/` | <프로토콜 처리> |
| `third_party/` | <외부 라이브러리. 절대 수정 금지 - 업스트림 패치로 관리> |
| `tests/` | <gtest 기반 단위 테스트> |

## 코딩 규칙

- C++ 표준: `<C++17>` / C 표준: `<C11>`
- 포맷: `clang-format -i` (설정은 `.clang-format`), 커밋 전 필수
- 네이밍: <함수 lowerCamelCase, 멤버 m_ 접두, 상수 kPascalCase 등>
- 에러 처리: <예외 사용 금지, 반환 코드 `<Status>` 사용> 
- 메모리: <raw new/delete 금지. `std::unique_ptr` / 사내 `<Pool>` 할당자 사용>
- 로깅: <`LOG_ERR()` 매크로 사용. printf 직접 호출 금지>

### 금지 패턴

- <`strcpy`/`sprintf` 금지 - `strlcpy`/`snprintf` 사용>
- <전역 변수 추가 금지>
- <`src/hal/` 에서 상위 레이어 헤더 include 금지 (순환 의존)>

## 디버깅

- 코어덤프 경로: `<​/var/crash/ 또는 ulimit -c unlimited 후 cwd>`
- 심볼 파일: `<build/bin/xxx.debug - 배포본은 strip 되어 있으므로 이걸 써야 함>`
- ASAN 빌드: `<cmake -DENABLE_ASAN=ON>`, 실행 시 `ASAN_OPTIONS=detect_leaks=1`
- 자주 나오는 크래시 패턴: <예 - `<Session>` 해제 후 콜백 진입, use-after-free 다발>
- 로그 위치: `<​/var/log/xxx/>`

## 응답 규칙

- 소스 파일을 제시했을 때 **직접 수정하지 말 것**. 수정안은 코드 블럭으로 제시하고,
  반영 여부는 내가 결정함.
- 설명에 함수명을 문장에 그대로 쓰지 말고 괄호로 표기할 것. 예: "해제 경로(freeSession)에서"
- 분석에 파일이나 gdb 출력이 더 필요하면 추측하지 말고 요청할 것.
- 간결하게. 서론/재확인 생략.

## 도구

- 코드 검색·심볼 조회·git 이력: `repo-mcp` 사용 (전체 파일 읽기보다 우선)
- 빌드와 에러 확인: `build-mcp` 사용 (원문 로그 대신 `parse_errors` 우선)
- 코어덤프 분석: `gdb-mcp` 사용
```

---

## 작성 체크리스트

- [ ] 빌드 명령이 **복사해서 바로 실행 가능한** 형태인가 (에이전트가 실제로 실행함)
- [ ] 심볼 파일 경로가 명시됐는가 (없으면 백트레이스가 `??` 로 나옴)
- [ ] 수정하면 안 되는 디렉터리가 명시됐는가
- [ ] 프로젝트 고유의 함정이 적혔는가 (에이전트가 반복해서 틀린 것을 발견할 때마다 추가)

## 운영 팁

이 파일은 한 번 쓰고 끝내는 게 아니라 **에이전트가 같은 실수를 두 번 하면 그때 한 줄 추가**하는
방식으로 키워야 함. 처음부터 완벽하게 쓰려 하면 길어지기만 하고 효과는 적음.

길이는 100줄 안쪽 유지. 넘어가면 모델이 뒷부분을 무시하기 시작함
(사내 모델은 컨텍스트 활용 능력이 상용 모델보다 떨어질 가능성이 높음).
